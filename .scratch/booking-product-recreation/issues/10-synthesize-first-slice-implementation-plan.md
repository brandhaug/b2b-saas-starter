# Synthesize First-Slice Implementation Plan

Type: task
Status: resolved
Blocked by: 03, 04, 05, 06, 07, 08, 09

## Question

After the preceding decisions are resolved, synthesize an agent-ready implementation plan for the first Booking Vertical Slice.

The answer should produce tracer-bullet implementation tickets with blocking edges, covering package/app scaffolding, domain capabilities, D1 schema and seed data, API contracts and handlers, Merchant App surfaces, Booking App flow, tests, and verification.

## Answer

The first Booking Vertical Slice is published as an 18-ticket tracer-bullet graph. Each behavior slice grows the shared D1 schema, migrations, deterministic Seed Booking Scenario, Effect capability, owning application surface, and tests together; there is no horizontal "build the whole schema first" ticket. The graph expands the Booking Product alongside the Starter, then contracts superseded Starter behavior only after every replacement branch is green, followed by a separate integration-verification and documentation ticket.

The implementation tickets, in dependency order, are:

1. [Establish the five-Worker Booking Product topology](./11-establish-five-worker-booking-product-topology.md) — blocked by nothing; makes all five settled Workers buildable, runnable, deployable, and correctly routed through the Public Site ingress.
2. [Move merchant authentication into the Merchant App](./12-move-merchant-authentication-into-merchant-app.md) — blocked by [Establish the five-Worker Booking Product topology](./11-establish-five-worker-booking-product-topology.md); moves the complete provider-light Better Auth owner lifecycle and isolated Merchant session boundary to its owning app.
3. [Onboard a verified Merchant Owner](./13-onboard-verified-merchant-owner.md) — blocked by [Move merchant authentication into the Merchant App](./12-move-merchant-authentication-into-merchant-app.md); introduces the first live Merchant graph, ownership authorization, default Provider, Unpublished Public Booking Page, D1 migration, and typed seed builder.
4. [Configure Providers, Services, and eligibility](./14-configure-providers-services-and-eligibility.md) — blocked by [Onboard a verified Merchant Owner](./13-onboard-verified-merchant-owner.md); makes the minimum Merchant Catalog configurable end to end and expands the canonical fixture.
5. [Configure Schedule Rules and publish a Public Booking Page](./15-configure-schedule-rules-and-publish-public-booking-page.md) — blocked by [Configure Providers, Services, and eligibility](./14-configure-providers-services-and-eligibility.md); makes recurring scheduling, derived readiness, publication, the public page, and the booking entry point work together.
6. [Start a capability-protected Booking Session](./16-start-capability-protected-booking-session.md) — blocked by [Configure Schedule Rules and publish a Public Booking Page](./15-configure-schedule-rules-and-publish-public-booking-page.md); replaces public prototype state with a private, resumable, D1-backed anonymous Session.
7. [Choose Provider Preference and Services](./17-choose-provider-preference-and-services.md) — blocked by [Start a capability-protected Booking Session](./16-start-capability-protected-booking-session.md); persists the source-faithful Solo/Team, Specific/Any Provider, Primary Service, and Additional Service journey.
8. [Hold a Time Slot and freeze the Booking Quote](./18-hold-time-slot-and-freeze-booking-quote.md) — blocked by [Choose Provider Preference and Services](./17-choose-provider-preference-and-services.md); delivers derived Availability, atomic holds, Any Provider assignment, immutable quotes, concurrency protection, and the scheduling UI.
9. [Capture Customer Details and review Pay In Person checkout](./19-capture-customer-details-and-review-pay-in-person-checkout.md) — blocked by [Hold a Time Slot and freeze the Booking Quote](./18-hold-time-slot-and-freeze-booking-quote.md); completes customer input and the provider-free Checkout review without creating Customer identity or payment state.
10. [Confirm an Appointment atomically](./20-confirm-appointment-atomically.md) — blocked by [Capture Customer Details and review Pay In Person checkout](./19-capture-customer-details-and-review-pay-in-person-checkout.md); commits the Appointment, immutable snapshots, Confirmation access metadata, terminal replay record, and durable outbox in one operation, then makes success visible independently of queue health.
11. [Serve the secure customer Confirmation](./21-serve-secure-customer-confirmation.md) — blocked by [Confirm an Appointment atomically](./20-confirm-appointment-atomically.md); delivers the clean, token-exchanged, narrowly scoped cross-device customer view.
12. [Operate Appointments and the Customer Directory](./22-operate-appointments-and-customer-directory.md) — blocked by [Confirm an Appointment atomically](./20-confirm-appointment-atomically.md); makes immutable confirmed facts visible in the Merchant App without introducing Appointment mutation or durable Customer identity.
13. [Bootstrap merchant-scoped Platform API Tokens](./23-bootstrap-merchant-scoped-platform-api-tokens.md) — blocked by [Onboard a verified Merchant Owner](./13-onboard-verified-merchant-owner.md); starts the parallel integration branch with Merchant settings bootstrap, exact scopes, API authentication, errors, rate limits, and audit behavior.
14. [Expose the read-only Platform API v1](./24-expose-read-only-platform-api-v1.md) — blocked by [Confirm an Appointment atomically](./20-confirm-appointment-atomically.md) and [Bootstrap merchant-scoped Platform API Tokens](./23-bootstrap-merchant-scoped-platform-api-tokens.md); publishes the settled Merchant, Service, Provider, and Appointment read contract plus OpenAPI while removing generic Starter groups.
15. [Configure Webhook Endpoints and inspect deliveries](./25-configure-webhook-endpoints-and-inspect-deliveries.md) — blocked by [Bootstrap merchant-scoped Platform API Tokens](./23-bootstrap-merchant-scoped-platform-api-tokens.md); implements safe endpoint and secret lifecycle plus PII-free delivery history before dispatch exists.
16. [Deliver booking notifications from the durable outbox](./26-deliver-booking-notifications-from-durable-outbox.md) — blocked by [Confirm an Appointment atomically](./20-confirm-appointment-atomically.md) and [Configure Webhook Endpoints and inspect deliveries](./25-configure-webhook-endpoints-and-inspect-deliveries.md); turns committed work into recoverable confirmation email and thin `appointment.created` deliveries without controlling booking success.
17. [Contract superseded Starter surfaces](./27-contract-superseded-starter-surfaces-and-verify-product.md) — blocked by [Serve the secure customer Confirmation](./21-serve-secure-customer-confirmation.md), [Operate Appointments and the Customer Directory](./22-operate-appointments-and-customer-directory.md), [Expose the read-only Platform API v1](./24-expose-read-only-platform-api-v1.md), and [Deliver booking notifications from the durable outbox](./26-deliver-booking-notifications-from-durable-outbox.md); removes the old Workspace-era and prototype forms only after every replacement branch is green.
18. [Verify and document the Booking Product](./28-verify-and-document-booking-product.md) — blocked by [Contract superseded Starter surfaces](./27-contract-superseded-starter-surfaces-and-verify-product.md); proves the entire journey, security and failure boundaries, clean and upgrade migrations, deterministic fixtures, five-Worker checks, and final documentation.

All blocking references resolve, every ticket is a child of this synthesis ticket, and the graph is acyclic. The initial implementation frontier contains only [Establish the five-Worker Booking Product topology](./11-establish-five-worker-booking-product-topology.md). After [Onboard a verified Merchant Owner](./13-onboard-verified-merchant-owner.md), the customer-booking chain and Platform API configuration branch can advance independently until Appointment confirmation joins their downstream work.
