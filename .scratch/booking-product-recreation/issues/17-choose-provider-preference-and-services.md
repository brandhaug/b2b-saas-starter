## Agent Brief

**Category:** enhancement
**Summary:** Persist the source-faithful Provider Preference, Primary Service, and Additional Service journey in an authorized Booking Session.

**Current behavior:**
The Booking App presents a fixture-backed Provider and Service flow whose selections live only in React state. Refreshes and server navigation lose the journey, Solo and Team behavior is not derived from Merchant Catalog data, and no server capability validates or persists the selected Provider Preference and Services.

**Desired behavior:**
Customers should choose a Specific Provider or Any Provider when Team behavior applies, while Solo journeys with one eligible default Provider skip the choice. They should select exactly one Primary Service and zero or more Additional Services from active, eligible Merchant Catalog data, with every accepted selection persisted in the capability-authorized Booking Session. Any Provider must remain the customer's original preference for later assignment, and rejected selections must not disclose private or cross-Merchant catalog facts.

**Key interfaces:**

- Booking Session selection capability — reads and changes Provider Preference and ordered Service selections only for the authorized, active Merchant-scoped Session.
- Public bookable catalog projection — exposes only active Providers, active Services, and valid Provider-Service eligibility needed by the current journey.
- Provider Preference contract — represents Specific Provider and Any Provider distinctly and preserves the customer's original choice.
- Service selection contract — distinguishes one Primary Service from zero or more Additional Services and enforces eligibility, uniqueness, and a single currency.
- Booking App selection routes and components — render persisted Session state with source-faithful Provider, Service, category, Additional Service, order-summary, and drawer interactions under the Merchant booking base.

**Acceptance criteria:**

- [x] Solo Sessions with one eligible default Provider skip Provider choice; Team Sessions offer Specific Provider and Any Provider without replacing Any Provider with a concrete assignment at this stage.
- [x] Exactly one eligible Primary Service and zero or more unique eligible Additional Services can be selected from active Merchant-scoped catalog data.
- [x] Inactive, invalid, cross-Merchant, duplicate, ineligible, and mixed-currency selections are rejected through non-disclosing errors and do not partially mutate the Session.
- [x] Accepted Provider Preference and Service selections survive refresh and server navigation because the authorized Booking Session is the source of truth.
- [x] The Provider grid, two-column Service cards, category treatment, Additional Service handoff, persistent order summary, and full-height drawer preserve the established StyleX interaction grammar.
- [x] Direct Booking Worker development and Public Site ingress preserve Merchant-scoped routes, redirects, links, and assets.
- [x] Capability, route, component, and ingress coverage proves ready, no-services, Solo, Team, Any Provider, refresh, and invalid-selection paths.

**Out of scope:**

- Availability calculation, concrete Any Provider assignment, Time Slot Holds, and Booking Quotes.
- Customer Details, checkout, Appointment confirmation, customer accounts, and Platform API booking mutations.
- Gift cards, group appointments, passcodes, waiting lists, walk-ins, and other Legacy Source extensions outside the first Booking Vertical Slice.
