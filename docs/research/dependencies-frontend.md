# Frontend, content, email and i18n dependency audit

Reviewed 2026-09-07 against the workspace catalog, package manifests, actual imports, `.fallowrc.json`, web/email intent nodes, and ADRs 0029, 0046 and 0063. Judgments below concern fit for this starter, not a claim that every installed release is the newest. The selected changes are implemented; see [the main audit](./dependency-audit.md) for integrated validation.

The existing stack fits Cloudflare Workers. Retain React and TanStack Start: replacing them with Next.js/OpenNext, React Router or Astro would rewrite routing, server functions, auth gates and locale handling without fixing an observed problem. TanStack maintains a [Cloudflare example](https://tanstack.com/start/latest/docs/framework/react/examples/start-basic-cloudflare). The important operational distinction is already documented in ADR 0063: standalone web builds externalize packages, while deployment bundles dependencies into the Worker. Installed package size is not uploaded Worker size.

## Changes justified now

`@react-email/components@1.0.12` and its individual component packages were marked unsupported in the starting `pnpm-lock.yaml`. The [official React Email 5-to-6 migration guide](https://react.email/docs/getting-started/updating-react-email) says components and rendering utilities now come from `react-email`; the preview application remains separately installed as `@react-email/ui`.

Migrated component and render imports to `react-email@6.9.3`, moved it to email runtime dependencies, removed direct `@react-email/components` and `@react-email/render`, and retained `@react-email/ui@6.9.3` in devDependencies. Installed `react-email` exports every component used here, including `Tailwind` and `pixelBasedPreset`, plus rendering utilities. Its package entry reexports the still-supported render package, so removing the direct declaration does not remove that transitive implementation.

This retires unsupported component packages while retaining current templates, transport and previews. The cost is import and manifest changes plus template/bundle validation. The unified package also contains CLI dependencies, but its ESM library entry and CLI entry are separate; do not assume those tools ship into Workers. Inspect the actual bundle. The email intent node and browser boundary assertion now cover the consolidated package and its component marker. The existing `css-tree` marker remains useful; `@react-email` alone is no longer sufficient evidence of coverage. [Current Button documentation](https://react.email/docs/components/button) and [upstream library entry](https://github.com/resend/react-email/blob/main/packages/react-email/src/index.ts) independently confirm the supported import path.

## Verification scope

Run catalog generation and web/email typechecks after declaration changes. For render-once email conversion, use existing delivery/template tests to confirm text retains reset/invitation links and both locales. A new UI-library migration would require keyboard navigation, escape/focus return, permission visibility and search-keyword tests. Any claimed Cloudflare upload saving must come from the deploy-shaped server build described by ADR 0063, not `node_modules` size or the standalone Vite output.
