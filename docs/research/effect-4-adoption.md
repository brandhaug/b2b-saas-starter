# Effect 4 adoption research

Verified 2026-10-29 against npm and upstream tag `effect@4.1.0`, commit `9a91b1926a5fbfaffd302a7a41a94d4d53a1154e`. The investigation started from Effect 4.0.6 and a SQLite DO override at 4.0.0. The inventory below describes that baseline; the upgrade section records changes made during this investigation.

## Upgrade implementation

- Aligned `effect`, `@effect/platform-node`, `@effect/sql-d1`, `@effect/vitest`, and the SQLite DO override to 4.1.0.
- Migrated the OpenAI adapter's `NetworkError` fields and removed obsolete diagnostic headers.
- Passed MCP registrations through the transport's `registrations` option. Resource handlers now explicitly capture stable capability services, as tool handlers already did. Caller and invocation context remain request-specific.
- The latest published Alchemy, `2.0.0-beta.84`, still imports the removed `effect/Crypto`. The tracked `patches/alchemy@2.0.0-beta.84.patch` migrates OAuth randomness and PKCE hashing to `SecureRandom` and `Digest`, supplies both Web Crypto layers in its platform runtime, and updates source, JavaScript and declarations. Remove the patch when an upstream Alchemy release includes this migration. The local runtime uses Node, not Bun; no remote deployment or interactive OAuth login is part of this verification.
- `scripts/alchemy-effect-compat.test.ts` exercises the installed Alchemy package and its platform layer. It verifies distinct state/verifier values and checks the S256 challenge against Node's independent SHA-256 implementation. Before patching, this test failed to import the removed Crypto module.

Reproduce the complete checks with `vp install --frozen-lockfile` followed by `pnpm run validate`. The focused dependency check is `vp test run scripts/alchemy-effect-compat.test.ts`.

### Observed validation

On 2026-10-29, frozen-lockfile installation and `pnpm run validate` both passed. Validation covered documentation exports, workspace typechecks, lint, formatting, dead-code and translation checks, package and script tests, production builds, Wrangler drift detection, local D1 migration/seed, and browser E2E. Chromium reported **65 passed, 11 skipped**. The skipped cases require configured browser analytics. The repeatable E2E report is generated at `apps/web/playwright-report/results.json`.

The Alchemy OAuth regression test passed under `@effect/vitest`. Existing API tests exercised the migrated MCP transport and resource handlers. OTLP compilation and tests passed with the existing wrapper: it deliberately exposes no service to callers and flushes through invocation-scope cleanup, so the newly exposed upstream `Flusher` does not require a wrapper signature change.

## Prioritized adoption candidates

### P0: preserve behavior across the 4.1 upgrade

- Migrate MCP registration composition in `apps/api/src/mcp.ts`, especially `mcpProtocolLayer`. The baseline separately merges registrations and transport and provides `McpServer.layer`; 4.1 takes registration layers through the transport's `registrations` option. Capture construction-time services through `Layer.unwrap` as prescribed upstream. Exercise initialization, list/read/call, token and OAuth callers, missing authority, cross-workspace sessions and concurrent requests. [R1], [MCP]
- Use the new MCP request-dependency mechanism to evaluate replacing `CurrentMcpCaller`'s defaulted `Context.Reference` with a required request service. The baseline explicitly uses an optional reference because handlers are built once. v4.1 removes that structural reason. Preserve per-call membership/consent checks and REST/MCP operation parity; a list-visibility predicate never replaces call authorization. This is a valuable follow-up if the smallest compatible upgrade retains the reference. [MCP]
- Update `AiError.NetworkError` construction in `packages/ai/src/openai.ts`: the old `request: { method, url, urlParams, headers }` becomes `method` and `url`. Remove the obsolete diagnostic header shape. The new optional `cause` preserves the original `HttpClientError` without redaction, so retain the repository's allowlisted outward failure data and logger sanitization. Do not blindly serialize or traverse that cause. [R1], [AI]
- Review `packages/logger/src/otlp.ts`'s explicit `Layer.Layer<never>` result. `Otlp.layer*` now correctly exposes `OtlpExporter.Flusher`. Preserve per-invocation construction and shutdown flushing; adjust truthful types rather than moving the exporter to an isolate or casting away its output. [R1]
- Audit package alignment, including transitive Effect users and the `@effect/sql-sqlite-do` override. D1 and Vitest 4.1 changelogs list dependency updates rather than standalone driver/test features. Node's package raises its minimum to 22.19.0 and changes WebSocket implementation. The starter's TS 7/Vitest 5 baseline meets Effect's general compiler/test requirements; the parent must verify the installed dependency graph and pinned Node runtime. [PKG], [R0]

### Optional 4.1 candidates

- The new `effect/crypto` family can replace duplicated Web Crypto wrappers in `packages/capabilities/src/crypto.ts`, `packages/billing/src/crypto.ts`, and `packages/failure/src/crypto.ts`. Digest, MAC and secure-random services offer typed failures and deterministic mocking. This is a focused adapter cleanup, not a reason to replace Better Auth, `jose`, or signing protocols. Explicitly provide Web Crypto layers and verify output bytes against existing fixtures. No direct use of the removed `effect/Crypto` was found in the import survey. [R1], [CRYPTO]
- RFC 9457 Problem Details can standardize external REST errors in `packages/api/src/errors.ts`. It changes the wire contract and generated clients, so defer until that API decision is made. Do not alter MCP JSON-RPC errors or expose schema internals by default. [R1]
- ISO duration codecs and ASCII checks are useful only for fields with those exact contracts. Existing human text and internationalized names must not acquire ASCII restrictions. CSV is relevant if an export feature explicitly requests CSV; current workspace export artifacts are JSON.
- CircuitBreaker is experimental and arrived in 4.0.7. Consider it only for a measured provider-failure problem with specified fallback and recovery. Keep queue-level delivery policy and no automatic inference replay. OtlpProxy, also 4.0.7, would add a browser telemetry ingestion endpoint and is deferred under the current observability design. [R7]

## Intervening 4.0.7 changes included in the upgrade

These are new relative to the repository's 4.0.6 baseline, but must not be reported as 4.1 introductions. [R7], [PKG]

- Directly relevant HTTP/MCP fixes include enforcing `MaxBodySize` on buffered web requests used by `toWebHandler`, preserving sanitized error URLs and HttpClient inspection, stacked OpenAPI security requirements, optional-parameter nullability, prefix routing, JSON-RPC error shapes without internal `_tag`, and disabling RPC control messages in MCP. Confirm oversized request behavior and generated OpenAPI alongside existing MCP tests.
- Runtime/stream fixes include traced function frames retaining arguments, duplicate interrupt reasons, semaphore fairness, mutable-array aliasing in queues, stream broadcast/group termination/buffer preservation and separation of upstream versus Sink failures. SSE parsing no longer loses the first BOM-prefixed event after an initial empty chunk. `packages/ai/src/provider-stream.ts` directly uses that parser.
- New HTTP capabilities include `HttpApiClient.decodeResponse`, multiple stream content types, buffered upgrade payloads and typed 101 headers. Redirect body release/query preservation, compression, static-server preconditions and cookies also receive fixes.
- New additions include experimental CircuitBreaker/client integration, OtlpProxy, property-test concurrency, CLI Presenter/completion generation/user-message annotations, and tool `toModelOutput`. OpenAI Responses gains PDF parts. These are mostly deferred here.
- Schema fixes cover representation/code generation, nested JSON Schema references, JSON-string content declarations, optional Record value rejection, Enum Record keys, checks preserving HTTP status, template literals, ULID bounds and Standard JSON Schema declarations. Generic tagged-enum emitted declarations require Effect 4.0.7 or newer.
- SQL/cluster changes include transaction-aware resolver batching, Durable Object transaction integration, empty SQL IN handling, event-journal statement limits, runner lock ownership and workflow replay/compensation fixes. Redis gains dedicated connection leasing. These do not replace application D1 batching or Cloudflare queue delivery.
- `@effect/vitest` adds `buildPerTest`, reports finalizer defects on test cancellation and fixes shared-layer lifetime under retries/repeats. D1's package notes list dependency updates. `@effect/sql-sqlite-do` specifically changes transaction behavior and deserves transitive compatibility review because the baseline overrides it to 4.0.0.

## Scope and evidence limits

Research inspected root architecture/guidance, Effect examples and the capabilities, API, AI, database and logger intent nodes, plus representative service, transport, provider, schema and runtime files. It surveyed Effect import families across apps/packages/scripts/infra. Sources include registry metadata, git tags, the complete 4.1 core changelog section, the 4.0 stable release overview, migration guides/maps, the 4.0.7 delta and relevant companion-package changelogs/source.

This is a broad adoption assessment, not a symbol-by-symbol audit of every beta release, every 4.0.1 through 4.0.6 patch, every provider/SQL/platform package, or every transitive dependency. Earlier patch fixes are already within the baseline; selected ones were checked to avoid wrong introduction claims. Source `@since` annotations alone are insufficient: the 4.1 crypto barrel says `@since 4.0.0`, while the release notes explicitly introduce the family-service replacement in 4.1. No benchmark, remote deployment or provider call was run. Local upgrade validation is recorded above. Release attribution uses the immutable upstream tag and the baseline catalog, rather than the installation being upgraded during research.
