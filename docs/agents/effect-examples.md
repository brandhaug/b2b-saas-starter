Use these files as local evidence before designing an Effect service, Layer, adapter, or test. They are examples to inspect, not tutorials to copy. Read the nearest intent node beside the target code first. For the pinned Effect version and workspace source of truth, read the `catalog` in [`pnpm-workspace.yaml`](../../pnpm-workspace.yaml) and the repository's package metadata before relying on remembered APIs.

## Repository exceptions

- Provider selection uses typed environment bags and `select*Layer` functions. Do not replace this with generic Effect `Config` advice. See [`packages/capabilities/src/runtime.ts`](../../packages/capabilities/src/runtime.ts), [`packages/env/src/server.ts`](../../packages/env/src/server.ts), and the capabilities intent node.
- Permission checks generally belong at the route, server-function, or worker caller. Capabilities rely on `WorkspaceContext`; when a capability-specific exception exists, follow its leaf intent node rather than applying a universal rule. See [`packages/capabilities/AGENTS.md`](../../packages/capabilities/AGENTS.md) and [`packages/authz/AGENTS.md`](../../packages/authz/AGENTS.md).
- Better Auth organization-plugin writes cannot share a D1 transaction with their audit row. Keep the plugin call and record the accepted divergence described in ADR 0051. Do not introduce a direct Drizzle write to force atomicity. See [`packages/auth/AGENTS.md`](../../packages/auth/AGENTS.md).
- D1 mutation plus audit uses `batch()`. `db.transaction()` is not an available substitute on Workers D1.
- Seed and Live are paired adapters for the demo identity. A new capability or mutation needs both, and its contract test should exercise both when the existing test shape applies.
