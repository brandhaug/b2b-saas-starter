# Merchant-scoped, network-fresh PWA

The customer-facing Merchant surface is installable as one PWA per Merchant. The Public Site owns the dynamic manifest and root service-worker script, while the Merchant landing page and canonical Booking routes advertise the same manifest and register the worker with the Merchant-rooted `/:merchantSlug/` scope. The manifest starts at the Merchant landing page, uses Merchant identity from the published D1-backed page, and carries standard and maskable icons. The manifest remains the authoritative installed-app identity; Booking routes do not invent a display name from the slug. The Merchant landing page provides the canonical D1-backed legacy iOS title, so legacy installation should begin there.

The service worker manages installation and activation only. It does not intercept or cache fetches, because availability, holds, checkout, authentication, and Appointment state must remain network-fresh. Offline booking, push notifications, background sync, and orientation locking are intentionally excluded until a concrete product use case defines their data, consent, accessibility, and invalidation contracts. This narrows and supersedes [0021](./0021-no-initial-pwa.md): the authenticated starter and editorial surfaces still do not become general-purpose offline applications.
