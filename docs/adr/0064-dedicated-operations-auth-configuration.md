# Use a dedicated Operations Auth configuration

`packages/auth` exposes `createOperationsAuth` rather than reusing `createAuth` or `createMerchantAuth`. It owns an Operations-specific secret, base URL, trusted origins, host-only `operations` cookie prefix, verified email/password flow, and Better Auth TOTP plus backup codes. Better Auth custom access control and multi-role assignments are the source of Operator Permissions, so no parallel System Operator or permission tables are introduced. The composable roles are `merchant-reader` (`merchant:read`), `merchant-impersonator` (`merchant:read` and `merchant:impersonate`), `impersonation-auditor` (`impersonation-audit:read`), and `operator-manager` (`operator:manage`). None receives stock admin user/session permissions or implicit full access; Effect capabilities check current Better Auth roles authoritatively from D1 on every protected request and enforce the additional Operations workflow invariants. Role removal takes effect immediately, while disabling an operator atomically revokes its Operator Session and derived impersonation. Merchant Auth remains narrow and unchanged.
