# Intent node documentation

The starter uses fresh `AGENTS.md` intent nodes rather than copied ones. The root node points to `CONTEXT.md`, `ARCHITECTURE.md`, and `DESIGN.md`, plus child intent nodes for the web app, API worker, background worker, database, capabilities, and observability so agent guidance matches the starter domain instead of leaking game-specific invariants. The capabilities node maps the per-capability leaf nodes under its bounded-context folders. Smaller packages such as auth and email do not yet carry their own intent node — their guidance lives in the consuming app nodes and package source until one grows enough to warrant a dedicated node, the way `packages/logger` did once its wide-event, tracing, and OTLP-export contract became a cross-cutting seam wide enough to need one of its own (`packages/logger/AGENTS.md`, symlinked from `CLAUDE.md` like every other node).
