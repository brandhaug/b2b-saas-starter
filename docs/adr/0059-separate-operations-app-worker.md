# Deploy the Operations App as a separate Worker

The staff-only Operations App lives in `apps/operations` as a TanStack Start application and deploys from its Vite server entry as a sixth Cloudflare Worker on its own origin. Typed TanStack Router routes and React screens own browser presentation, while server functions and explicit server routes adapt the existing Effect capabilities and Better Auth handler. It shares D1 and application capabilities with the Booking Product but owns a separate Better Auth configuration, host-only `operations` cookie namespace, deployment secret, and rate-limit boundary. Keeping it outside the Merchant App prevents platform authority and operator credentials from becoming merchant routes or browser credentials, at the cost of an explicit cross-origin impersonation handoff. The Start migration changes no persisted schema and keeps readiness, auth callbacks, local email capture, and the URL-free top-level POST impersonation exchange as explicit HTTP contracts. Cloudflare Access protection is deferred and is not a first-slice deployment prerequisite.
