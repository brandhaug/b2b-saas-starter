# Wrap Better Auth impersonation in an Effect capability

The Operations App does not expose or call Better Auth's stock `/admin/impersonate-user` endpoint. A dedicated Effect capability owns Operator Permission and fresh-TOTP checks, target eligibility, Impersonation Reason, single-flight concurrency, one-time handoff tickets, reduced Merchant authority, authoritative revocation, and atomic audit events. Better Auth remains the engine for identities, two-factor authentication, session persistence, and `impersonatedBy` provenance, but product policy is not delegated to a generic plugin endpoint that cannot express the agreed safeguards. Implementation begins with an integration spike proving separate secrets and host-only cookies, ticket consumption and replay rejection, Merchant-session creation and stop/return behavior, existing-session rejection, and fail-closed lifecycle activation before Operations UI work begins.
