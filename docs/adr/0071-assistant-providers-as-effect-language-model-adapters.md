# Assistant providers as Effect LanguageModel adapters

`packages/ai` now runs the assistant on `effect/unstable/ai` (ADR 0008's "prefer Effect AI patterns" made real): there is one `ask` implementation, `AssistantLive`, which builds a normalized `Prompt` — a system message naming the workspace, a user message carrying the question — and calls `LanguageModel.generateText`. Which model answers is a layer decision: each provider is a `LanguageModel` adapter built with `LanguageModel.make` and wrapped in `Model.make`, which stamps `ProviderName` and `ModelName` beside the model it provides. The reply's `provider` and `modelId` fields are read back from that same context (the one place a string crosses back into the reply's literal union, guarded by the schema), so they cannot disagree with the model that actually answered. The three adapters — the Workers AI binding (Cloudflare-first), an OpenAI-compatible `/chat/completions` call over the single `postJson` boundary, and the honest mock that echoes the question and names the env vars that would enable a real provider — live in one module each (`workers-ai.ts`, `openai.ts`, `mock.ts`) and differ in nothing but how they call their provider and encode its answer: the whole acceptance policy ("text only: no tools, no structured output, no prompt richer than system and user text messages") is one shared prelude, `plainChat` in `text-model.ts`, that every adapter applies before any request is sent. `selectAssistantLayer` composes `AssistantLive` over the env-selected model, and `isAssistantConfigured` still reads the same `ProviderChoice`, so selection, the UI's "not enabled" copy, and the ask path share one condition exactly as before; no provider package (`@effect/ai-openai` and friends) enters the catalog.

Errors now speak `AiError` inside the adapters — the OpenAI adapter maps transport failures to `NetworkError` (with the credential redacted in the reported request headers, the schema's `Redacted` arm) and HTTP statuses through `reasonFromHttpStatus` (429 becomes `RateLimitError`, 5xx `InternalProviderError`), the binding adapter reports a missing response as `InvalidOutputError` — and the one boundary that maps them is `AssistantLive`, into the `AssistantUnavailable` (503) the HTTP contract declares. The adapters refuse what they cannot represent honestly rather than approximating it: `streamText` fails with a typed `InvalidRequestError` until one implements it, and `plainChat` refuses tools, structured output, and prompts carrying anything but system/user text messages as `InvalidRequestError` / `UnsupportedSchemaError` / `InvalidUserInputError` instead of silently flattening or dropping them.

Trades accepted: the mock no longer names the workspace in its reply (the system message carries the slug to real providers; the mock's job is the honest not-enabled copy, and it now reads the question out of the normalized prompt rather than parsing prose), the finish part claims `stop` with empty usage for providers that report neither (Workers AI's binding returns bare text; the OpenAI adapter does decode `finish_reason`), and `usedTools` stays an empty array — `Toolkit`/`Tool` land in `AssistantLive` unchanged the day the assistant grows tools, which is the other half of what adopting the module buys.
