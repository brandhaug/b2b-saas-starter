# System Admin impersonation

The starter exposes Better Auth admin-plugin impersonation to System Admins, now that the three preconditions ADR 0024 set are met: audit logging, visible impersonation state, and session safety controls.

An impersonation session is Better Auth's: `admin.impersonateUser` mints a session for the target user with `impersonatedBy` set to the admin, swaps the browser's session cookie, and parks the admin's own token in a signed `admin_session` cookie; `admin.stopImpersonating` reverses it. The session lasts one hour (`impersonationSessionDuration`, stated in `packages/auth`), and `allowImpersonatingAdmins` stays `false`, so a System Admin is never impersonated and no impersonation session ever carries `/admin`. The impersonated session has exactly the target user's roles — nothing is elevated, and the workspace guard keeps refusing a system admin who is not a member.

The behaviour lives in the governance capability `PlatformUserAdmin` (`startImpersonation`, `stopImpersonation`), Seed and Live alike, behind the same structural binding port as ban/unban (ADR 0051's pattern: the plugin endpoints are `requireHeaders: true`, so the app supplies the adapter per call). The capability refuses an unknown target, a System Admin target, and self-impersonation before calling the binding, records `system_admin.impersonation_started` / `system_admin.impersonation_stopped` against the admin (actor) and the target (user), and writes a Notification to the impersonated user through `NotificationFeed.notifyUser` at start — the one moment guaranteed to happen, since a session the admin never stops simply expires. The audit rows are written after the plugin call, not batched with it, for the reason ADR 0051 records.

Visible state: `WorkspaceShell` renders a persistent banner on every gated page while `session.impersonatedBy` is set, naming the impersonated user with a Stop control. The shell reads the state off the route context rather than as a prop, because every gated route already carries `session` and the banner must appear on all of them.

Session safety: an impersonation session may not change the account's password, second factor, or email, or delete the account. The rule is the capability's (`IMPERSONATION_FORBIDDEN_ACTIONS`, `refuseWhileImpersonating`); the web app maps Better Auth's endpoints onto it in `apps/web/src/lib/server/impersonation-guard.ts` and answers 403 from the auth catchall before Better Auth runs, and `/account` hides the matching controls. The `admin.impersonate-user` / `admin.stop-impersonating` rows of the catchall audit table stay for direct client calls; the app's own flow goes through server functions and is audited by the capability, so each start and stop records once.
