# OpenTelemetry export, scoped per invocation

Wide events (ADR 0007) answer "what happened in this one request." They do not answer "where did this request go next," because each service emitted its own line under its own `x-trace-id`. `packages/logger` now also produces OpenTelemetry traces and metrics from the same scope that emits the wide event, and exports all three signals over OTLP/HTTP when `OTEL_EXPORTER_OTLP_ENDPOINT` is set. Effect v4 ships the integration in core (`effect/unstable/observability`), so this adds no dependency: `withRequestScope` opens a real span, `HttpTraceContext` decodes inbound `traceparent`/`b3` into that span's parent, and Effect's `HttpClient` injects the headers outbound and spans D1 queries reached through the `@effect/sql-d1` client on the way through. The queue is the one hop HTTP headers cannot cross, so `WebhookPublisher` stamps `currentTraceparent` onto the message and the background consumer continues that trace. `x-trace-id` stays as the value a support ticket can quote, and now defaults to the OTel trace id so it resolves in both places.

**The export layer is built per invocation, never per isolate.** This is the load-bearing decision. Cloudflare Workers refuse I/O performed on behalf of a request that has already ended, and Effect's OTLP exporters flush from a background fiber and from a scope finalizer. An exporter created once per isolate — the obvious shape, and the one every other layer in this repo uses — would flush during the request that created it and then fail silently for the life of the isolate. All three workers now split the same way: `WideEventLoggerLive` (console JSON plus the tracer logger) is provided isolate-level — the router layer in `apps/api`'s `http.ts`, and a module-scope `ManagedRuntime` in `apps/web`'s `src/lib/observability.ts` and `apps/background`'s `src/index.ts` — while `makeOtlpLayer(service, env)` is provided per invocation with `Effect.provide(..., { local: true })` inside it: `observed()` per request in the API worker, `runWebRequestScope` in the web worker, the `queue`/`scheduled` entry points in the background worker. Its scope closes while the invocation can still make requests, and the shutdown flush is what actually ships the batch. The split also matters for a second reason: `makeOtlpLayer`'s `loggerMergeWithExisting` only has isolate-level console loggers to merge with because they were provided outside the per-invocation scope it lives in.

The web worker needed one more piece. TanStack Start fans a single HTTP request out into many independent `Effect.runPromiseExit` calls — one per loader, one per server function — which produced a wide event and a root trace _per loader_: neither a wide event nor a usable trace. A global request middleware (`apps/web/src/start.ts`) now opens exactly one scope per request and registers it in a `WeakMap` keyed by the request object; `withWebRequestScope` looks it up through `currentRequest()` (`apps/web/src/lib/request-context.ts`) and runs nested work as a child span sharing the request's exporters, folding its annotations into the one canonical line. The registry is keyed by request rather than held in a module variable because a Worker isolate interleaves concurrent requests. `request-context.ts` isolates the `createIsomorphicFn`/`getRequest` call behind `currentRequest()`, which keeps `getRequest` out of the browser bundle, returns `undefined` rather than throwing when there is no ambient request, and is the one seam the tests mock. When there is no request to join — a client-side navigation re-running loaders against the Seed layer, or a standalone test — `withWebRequestScope` falls back to its own scope and tags the event `scope: 'standalone'`, so a missed join shows up in the log stream instead of silently producing an extra root trace. The web auth gates (`src/lib/server/auth.ts`, `src/lib/server/admin.ts`) now join the request scope through `withWebRequestScope` too, rather than running on `authRuntime` with no logger, span, or exporter.

> **Amended 2026-08-22:** The env-derived observability/module status reporting this decision originally described was removed in the feature-pruning sweep (issue #103). The per-invocation OTLP scoping below is unchanged.

> **Amended 2026-08-24:** `SENTRY_DSN` and `POSTHOG_KEY` are no longer reserved hooks (`packages/logger/src/providers.ts`). Both providers are wired as fetch-based ingestion — no vendor SDK, the same posture as this ADR's OTLP layer — and are consumed from the wide-event scope's exit path: every failed scope in all three workers is reported to Sentry's store endpoint and captured as a PostHog `$exception` when their vars are set. The invocation-scoped flushing rule applies unchanged: reports fire inside the invocation while I/O is still allowed, never from a background fiber, and transport failures are swallowed so observability cannot fail a request. Unset vars leave a shared inert provider set — nothing loaded, nothing sent.

The OTLP wiring also changed the observability posture: `OTEL_EXPORTER_OTLP_ENDPOINT` alone produces live end-to-end telemetry, while `SENTRY_DSN` and `POSTHOG_KEY` remain reserved activation hooks because neither SDK is wired. `.oxlintrc.json`'s dictionary-and-`object`-parameter exemption, previously scoped to `packages/logger/src/**` because the wide-event logger's contract is arbitrary structured annotations, now also covers `apps/web/src/lib/observability.ts` — the web half of that same seam, building the same open-shaped per-request telemetry context.

The alternative was `@microlabs/otel-cf-workers` or the vendor OTel SDKs, which would mean a second instrumentation stack beside Effect's tracer and no automatic spans for Effect operations. Sentry and PostHog remain unwired reserved hooks (ADR 0007's position is unchanged); an OTLP collector in front of them is the supported path. Without a configured endpoint the layer is `Layer.empty` and nothing changes: the console JSON event still goes to Cloudflare Workers Logs, which is the provider-light default the starter promises.
