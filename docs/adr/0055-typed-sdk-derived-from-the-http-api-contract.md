# Typed SDK derived from the HTTP API contract

`@b2b-saas-starter/sdk` (`packages/sdk`) is the typed client for the REST Capability Interface. It is derived at type-check time from the shared `StarterApi` definition in `packages/api` through Effect's `HttpApiClient`, so every path, query parameter, payload, success schema, and error schema the worker serves is the one the client encodes and decodes. There is no OpenAPI codegen step and no generated file to commit: a contract change fails the SDK's type-check, and the served `/openapi.json` stays a document for humans and third-party generators rather than an input to this repository's build.

The package exports two layers over the same client. The Effect-native factory returns the `HttpApiClient` for callers already running Effect. The plain client, `createStarterClient({ baseUrl, apiToken })`, wraps it in promise-returning methods, attaches the API Token as a bearer header, defaults to the runtime's `fetch`, and accepts an injected `fetch` so tests can point it at the API worker's web handler without a network. It also offers an async iterator that walks a paged list (ADR 0054) to exhaustion.

Codegen from the running `/openapi.json` was considered and rejected. The generated types would be a second copy of the contract with its own drift surface, a build step would have to boot the worker to fetch the document, and the client would lose the tagged error classes the contract already declares. The cost of the chosen approach is that the SDK depends on `@b2b-saas-starter/api` and, transitively, on `packages/capabilities` for its schemas, so it is a workspace package rather than a standalone publishable artifact today. Publishing it externally would mean extracting the schemas from the capabilities package first; that trigger has not fired (ADR 0048).
