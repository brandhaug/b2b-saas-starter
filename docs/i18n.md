# Translating the starter

The starter ships English, `en`, and Norwegian Bokmål, `nb`. Shared Paraglide
messages live in `packages/i18n/messages/<domain>/en.json` and `nb.json`.

## Add or change copy

Keep each complete sentence in a message, including its variable placeholders.
Add the same key to both catalogs. Use a domain prefix to avoid collisions with
other catalogs. Nested keys compile to underscore-separated function names.

```json
{
  "workspace_greeting": "Welcome to {workspaceName}"
}
```

Call the generated function when rendering the page or handling the request.
Evaluating a message in a module-level constant fixes its language at module load.

```tsx
import { m } from '@b2b-saas-starter/i18n/messages'

function Greeting({ workspaceName }: { readonly workspaceName: string }) {
  return <h1>{m.workspace_greeting({ workspaceName })}</h1>
}
```

Emails and background jobs pass the recipient's locale explicitly. A worker can
send messages in several languages during one invocation.

```ts
m.workspace_greeting({ workspaceName }, { locale: recipient.locale ?? 'en' })
```

Use Paraglide variants for plural forms instead of appending an English `s` or
assembling sentence fragments. Keep resource identifiers, code examples, and
user-written content unchanged.

## Generate and verify

Root development, build, typecheck, and test commands generate the catalogs.
The web Vite integration also generates them for direct web builds and refreshes
the page after catalog edits. You can run generation on its own:

```bash
pnpm -C packages/i18n generate
pnpm run check
```

Generation rejects missing translations, duplicate keys, and inconsistent
placeholders. Generated files are ignored by Git; edit the source catalogs.
The compiler uses the installed message-format plugin and needs no translation
service or CDN connection.

Browser tests cover language switching, page refresh, public navigation, and
warnings about form edits. If another worktree uses the default port, select a
free one:

```bash
E2E_PORT=3097 pnpm -C apps/web exec playwright test e2e/i18n.spec.ts
```

## Language and formatting behavior

Public URLs carry `/en` or `/nb`. Authentication and app URLs stay unprefixed.
Guests use a remembered language cookie or browser preference. The authenticated
app and emails use the account preference. Changing language reloads the page.

Use the shared formatting functions in `@b2b-saas-starter/i18n/format` with an
explicit locale and time zone. Web timestamp helpers read the settings serialized
with the document, so SSR and hydration use identical values. Anonymous pages
use UTC. Browser detection initializes an unset account time zone after login;
existing preferences do not change when someone travels.

Existing technical docs and blog articles remain English, including inside the
Norwegian navigation. New translations of long-form content require their own
reviewed content files. The catalogs do not translate Markdown or user content
automatically.

See [ADR 0074](./adr/0074-account-locales-and-shared-message-catalogs.md) for the
scope and architecture decisions.
