# apps/api

Cloudflare Worker for external interfaces. Dev server on `:8787`. **Serves the `StarterApi` HttpApi contract (`@b2b-saas-starter/api`) directly** via `HttpRouter.toWebHandler` — no Hono, and no hand-maintained route table. The web app does **not** consume this; this is the surface for external clients and MCP.

## How it's wired

- `src/index.ts` — thin `fetch` that delegates to a per-isolate web handler (`getWebHandler(env)`).
- `src/env.ts` — Cloudflare bindings + env type, plus `starterEnv(env)` for the capability layer.
- `src/http.ts` — assembles the app layer: `HttpApiBuilder.layer(StarterApi, { openapiPath: '/openapi.json' })`, the Scalar UI (`/reference`), Workers-safe platform services, and request-scoped capabilities via `HttpRouter.provideRequest`.
- `src/handlers.ts` — one `HttpApiBuilder.group(...)` per contract group: health, workspace, api-token-registry, webhook-endpoints, workspace-exports, assistant, mcp.
- `src/export-download.ts` — the signed export download (`GET /exports/:exportId/download?expires&signature`, ADR 0055), a public route beside the contract like `/mcp`: the signature is the credential, the capability verifies it, and every refusal is one 404.
- `src/request-guards.ts` — the per-request enforcement helpers (`authenticate`/`verifyToken`, `enforcePermission`, `enforceRateLimit`, `observed`, `provideWorkspace`) plus `bearerAuth(env)`, the implementation of the contract's `BearerAuth` middleware. Shared by the contract groups and the MCP protocol route.

## Owned today

- **REST** — workspace routes for overview, members, notifications, api-tokens, webhooks, audit-events, plus token create/revoke/delete, webhook create, workspace export request + download-link, assistant, and MCP discovery. Paths, params, payloads, success/error schemas, and status codes come from `packages/api`.
- **Workspace export** (ADR 0055) — `POST /workspaces/:slug/exports` (`workspaceExport:request`, 202 with the pending row) and `POST /workspaces/:slug/exports/:exportId/download-link` (`workspaceExport:download`, mints the signed URL on this request's origin; 404 `WorkspaceExportNotDownloadable` for anything not ready). Both statements are owner-only, so only an `admin`-scoped token reaches them — the permission matrix asserts 403 for the read token. The download itself is `GET /exports/:exportId/download`, public and signed, rate-limited on `rest_read`, not in the OpenAPI document (`index.test.ts` asserts that).
- **Per-request `WorkspaceContext`, and only that** — `provideWorkspace` builds `selectWorkspaceContextLayer(starterEnv(env), slug)`, the one service a request genuinely lacks; `WorkspaceNotFound` flows through as the contract's 404. Every other capability service is request-independent and is built once per isolate in `http.ts`, so a request pays for the workspace lookup and nothing else. The MCP tool callbacks capture that same context (`Effect.context`) and carry it across the SDK's promise seam instead of rebuilding the graph per tool call. Capability methods still never receive a slug parameter.
- **OpenAPI + Scalar** — `/openapi.json` is emitted by `HttpApiBuilder` from the contract; `/reference` is served by `HttpApiScalar.layer`. No `openapi.ts`/`reference.ts` files.
- **Bearer auth is contract middleware; permissions stay in the handler.** `BearerAuth` (declared in `packages/api`, implemented by `bearerAuth(env)` here) carries `security: { bearer: HttpApiSecurity.bearer }` and is attached with `HttpApiGroup.middleware` to every group but `health`. It draws the group's rate-limit bucket, verifies the decoded credential through `ApiTokenRegistry.verifyBearerToken`, and provides an `ApiPrincipal`. Because the gate is declared, the served OpenAPI carries `securitySchemes` and marks every gated operation — an endpoint cannot forget it. A handler then composes only `enforcePermission(permission, expectedWorkspaceSlug?)`, which reads that principal and asks `requirePermission` from [`@b2b-saas-starter/authz`](../../packages/authz/AGENTS.md) whether its scopes cover the route's permission. Unknown or revoked tokens map to `Unauthorized` (401), a denied permission and a workspace mismatch to `AuthorizationDenied` (403), and capability outages to `CapabilityUnavailable` (503). Workspace routes pass the URL slug so a workspace-A token cannot unlock workspace B. The gate runs before the handler body, so a rejected request emits its own wide event from the middleware rather than none at all.
- **Endpoints name permissions, not scopes.** `enforcePermission({ apiToken: ['create'] }, params.slug)`, never `'admin'`. The scope-to-permission mapping lives in one place — `authz`'s role table — so a bearer token here and a session in the web app resolve through the same `authorize()` call.
- **This worker does not mutate membership, and serves no invitation endpoint.** Settled by issue #64. Every invitation endpoint on Better Auth's `organization` plugin is `requireHeaders: true`, `createInvitation` additionally requires the caller to be a workspace member holding `invitation:create`, and `removeMember` / `updateMemberRole` need headers too — a bearer token is no session. Rather than mint a session for the token's creating user (a second authority beside `authorize()`, which decision 8 of the map exists to avoid) or write around the plugin, the write surface stays in `apps/web` (see [`workspace-invitations`](../../packages/capabilities/src/governance/workspace-invitations.AGENTS.md)). `POST /workspaces/:slug/invitations` was **removed from the contract**: it emailed a link carrying no invitation id, so no recipient could ever accept it. Member and invitation **reads** are unaffected. Do not add a membership write here without answering the session question first.
- **No email wiring here.** With the invitation endpoint gone the worker has no `EmailDispatcher` consumer, so `selectEmailDispatcherLayer` is not in its layer stack and `ApiEnv` carries no `EMAIL` binding. The email path's wired consumer is `apps/web/src/lib/server/invitations.ts`.
- **Webhook fan-out** — lives inside the mutating capabilities (`ApiTokenRegistry` create/revoke, `WebhookEndpoints.create`), beside their audit writes: handlers compose only gate + capability call. Publishing is best-effort (`publishWebhookEventWith`): queue outage annotates the wide event but never fails the response. The producer binding is `WEBHOOK_QUEUE`; without it the publisher no-ops. Because the fan-out sits below the capability interface, the web app's session surface fires the same events as REST.
- **Rate limiting** — the bucket union, the `RateLimiter` service, and the group-to-bucket table live on the contract beside `BearerAuth` (`rateLimitBucketFor`), because an endpoint is limited by virtue of carrying the gate; `src/rate-limit.ts` keeps the mechanism — bindings, fallback limits, the layer — as a config shim over `@b2b-saas-starter/rate-limit`. Four buckets are bound in `wrangler.jsonc`: `rest_read`, `rest_write`, `assistant`, `mcp`. A gated group with no row fails closed with `CapabilityUnavailable`; `permission-matrix.test.ts` asserts there is none. The `invitations` bucket went with the invitation endpoint — a bound rate limiter with no route is dead config.
- **MCP protocol** — `src/mcp.ts` serves a real MCP server at `POST /mcp` via `createMcpHandler()` from the Cloudflare Agents SDK over an MCP SDK v2 server factory (`@modelcontextprotocol/server`), stateless per request — no session, no Durable Object. The route rides beside the contract via `HttpRouter.add`; it never appears in the OpenAPI document. After the bearer-token gate proves `mcp:read`, the handler is handed the pre-parsed body through `fetch(request, { parsedBody })`. The endpoint is strict stateless-only (`legacy: 'reject'`): clients speak the 2026-07-28 modern revision — per-request `_meta` envelope plus the reserved `Mcp-Method`/`Mcp-Name` headers, which the route forwards to the handler — and legacy-handshake clients get `-32022`. Tools are read-only projections over the same capability services REST uses, derived from the shared operation table (`src/operations.ts`) rather than hand-mirrored — one tool per workspace REST read, same permission, same capability read, with `mcp.test.ts` failing if anything stops being derived from that table — and each invocation re-checks its own permission against the token's scopes. `GET /mcp` remains the contract-served discovery document; it is derived from the same table, so all three surfaces cannot drift. The route owns no transport of its own: `HttpServerRequest.toWebResult` / `HttpServerResponse.fromWeb` convert between the router's request and the Agents handler's, and a guard failure before the protocol is reached is encoded by the contract's `guardFailureResponse` — status from the error schema's `httpApiStatus` annotation, body from the schema itself — so `POST /mcp` rejects a request byte-for-byte the way a REST route does.
- **Shared request guards** — `src/request-guards.ts` holds `authenticate`/`verifyToken`, `enforcePermission`, `enforceRateLimit`, `observed`, `provideWorkspace`, and the `BearerAuth` implementation. The contract groups get auth from the middleware; the MCP protocol route (`POST /mcp`) is not a contract endpoint, so it composes `enforceRateLimit` + `authenticate` itself — through the same helpers. Do not grow a second auth path for a new surface.

## Conventions

- Behavior lives in `@b2b-saas-starter/capabilities`. Don't reach to Drizzle from this worker.
- To add or change a route, edit the `StarterApi` contract in `packages/api` first, then add or adjust its handler in `handlers.ts`. The contract is the single source of truth.
- Each handler wraps its body in `observed(...)` and composes the `enforcePermission` guard. Bearer auth and the rate-limit bucket come from the contract's `BearerAuth` middleware, so a handler never reads the `Authorization` header. A guard adds only the errors it can raise, so each endpoint's error channel must be a subset of its declared contract errors.
- `observed(...)` is also where OpenTelemetry lives, and it owns none of the recipe: it hands the worker's own `Request` (reached through `HttpServerRequest.toWebResult`, the same conversion `mcp.ts` uses) to `withHttpInvocation` from [`@b2b-saas-starter/logger`](../../packages/logger/AGENTS.md), which continues the inbound `traceparent`/`b3`, opens the server span, enriches with env + the request's cf colo, and provides `makeOtlpLayer('api', env)` with `Effect.provide(..., { local: true })` — a fresh exporter per request, never per isolate (ADR 0050). `http.ts` provides only `WideEventLoggerLive` at the isolate level, since it writes to the console and needs no I/O. When a handler needs a trace id to hand back to a caller (e.g. `InternalError.traceId`), read `currentTraceId` — never mint a fresh one.
- Request payload shapes come from the contract. Tighten schemas in `packages/api` or `packages/capabilities`; do not hand-roll local validation.
- Cross-cutting requirements (capabilities, rate limiter, assistant) are provided to the request effect with `HttpRouter.provideRequest`. The same layer _value_ is also `Layer.provide`d to the api layer, because `BearerAuth` resolves its services from the group layers' build context; one value means one build — the memo map `provideRequest` forks reuses it, so the gate and the handlers share one instance of every capability service. Note what that does and does not mean: the layer is **built once** when the app layer is built, and its context is then provided to every request effect. It does not rebuild per request. Anything that must genuinely be per invocation — the OTLP exporters — goes through `Effect.provide(..., { local: true })` inside `observed` instead.
- Both route assembly and workspace routes build capability env through `starterEnv(env)` (`src/env.ts`). This worker sends no email, so it accepts no `EMAIL_FROM_ADDRESS` alias.
- Tests drive `buildWebHandler(env)` with web-standard `Request`s — the fastest way to assert routing, auth, status codes, and the served OpenAPI. `src/index.test.ts` covers routing and the auth failures; `src/permission-matrix.test.ts` covers the route-to-permission table, one row per gated operation, all driven by the seed `read`-scope token. That file's first test reads `/openapi.json` and asserts the served operations **equal** the matrix, so a new endpoint fails the suite until someone decides what a read-only token gets from it; a second asserts the document's `securitySchemes` and that the operations marked secured are exactly the matrix, and a third that every group carrying `BearerAuth` names a rate-limit bucket.
