The web, API, and background Workers need the same workspace rules. Keeping
those rules in `packages/capabilities` lets each Worker choose its transport
without duplicating authorization or business behavior.

Effect services make dependencies explicit. Live layers use D1; Seed layers
provide the same interfaces in memory. A capability test can exercise a use case
without booting a Worker.

Effect Schema connects capability values to the HTTP contracts in `packages/api`.
Those contracts drive routing, OpenAPI, and the typed SDK. MCP tools call the
same operation implementations and apply their own transport error handling.

Expected failures have tagged types, such as `WorkspaceNotFound` and
`AuthorizationDenied`. Each caller handles them at its boundary: HTTP status,
MCP tool error, or safe UI message. Unexpected failures stay distinguishable for
logging and investigation.

See [Effect v4 backbone](/docs/architecture/effect-v4-backbone) for the current
package boundaries.
