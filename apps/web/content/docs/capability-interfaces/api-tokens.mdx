API Tokens are the credential type for REST and MCP. They belong to a Workspace, never to a user account.

## Creation

A workspace admin creates a token from the API tokens page (`/workspaces/:slug/api-tokens`, gated on `apiToken:create`; the settings page links to it). The web app calls `ApiTokenRegistry.create` directly through a server function — the API Worker's `POST /workspaces/:slug/api-tokens` is the same capability's external surface for programmatic callers. The token's plaintext value is shown exactly once at creation — `randomToken()` in `packages/capabilities/src/developer-platform/api-token-registry.ts` returns a `bsk_live_<48-hex>` value; D1 stores only the SHA-256 `tokenHash` and a 17-character `tokenPrefix` for display. `ApiTokenRegistry.create` requires `WorkspaceContext` (supplied by the route layer from the URL slug) and writes an `api_token.created` Audit Event through `AuditEventLog.record`.

## Scopes

Scopes are coarse on purpose: `read`, `write`, and `admin`. Each scope maps to a set of permissions in `@b2b-saas-starter/authz`, so a scope and a workspace role are answered by the same `authorize()` call.

The API Worker's `enforcePermission(request, permission)` guard (`apps/api/src/handlers.ts`) parses the `Authorization: Bearer …` header, calls `ApiTokenRegistry.verifyBearerToken(token)` to authenticate, then checks the route's permission against the token's scopes. A missing header or an unknown token is HTTP 401; a token that may not do what it asked is HTTP 403. Handlers name the permission — `{ apiToken: ['create'] }` — never a scope. Minting a token needs the `admin` scope: `write` deliberately cannot create tokens, because a `write` token allowed to mint could issue an `admin` one. The MCP discovery endpoint at `/mcp` needs only workspace read access; per-tool permissions will follow once tool dispatch is wired.

## Revocation

Revocation is immediate, from the API tokens page (`apiToken:revoke`) or the external endpoint. `ApiTokenRegistry.revoke` stamps `revokedAt` on the row and `verifyBearerToken` filters `isNull(revokedAt)` — subsequent requests get HTTP 401, the same answer as any unknown token. Revocation also writes an `api_token.revoked` Audit Event via `AuditEventLog.record`; user-facing Notification emission on revocation is not yet wired.

## Using the API from code

The typed SDK is the programmatic counterpart of this page's token: it authenticates with an API Token and walks the same paged lists the REST routes serve.

```ts
import { createStarterClient } from '@b2b-saas-starter/sdk'

const client = createStarterClient({
  baseUrl: 'https://api.example.com',
  apiToken: 'bsk_live_…' // minted above, shown exactly once
})

// One Page of the workspace's audit events (newest first).
const page = await client.workspace.auditEvents('acme', { limit: 100 })

// Or every notification, cursor handled for you.
for await (const notification of client.workspace.notifications.iterate('acme')) {
  console.log(notification.title)
}
```

See [Typed SDK](/docs/capability-interfaces/sdk) for the Effect-native client and the error model.

## What tokens are not

API Tokens are not user sessions, not OAuth client secrets, and not provider API keys. They are a Workspace-scoped programmatic credential intended for the starter's public REST and MCP traffic.
