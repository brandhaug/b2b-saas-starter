Sentry and PostHog are optional, env-gated providers: they activate when their environment variables exist and stay absent when they do not.

Telemetry export does not depend on either of them: setting `OTEL_EXPORTER_OTLP_ENDPOINT` ships traces, metrics, and the canonical log records to any OTLP collector, which is the supported path today.

## Sentry

`SENTRY_DSN` is an optional field in `packages/env/src/server.ts`'s schema. No Worker-side Sentry SDK is initialized — the wiring point is reserved. Tagged-error → Sentry mapping and Alchemy source-map upload are explicit non-goals for the first slice.

## PostHog

`POSTHOG_KEY` (and optionally `POSTHOG_HOST`) behaves the same way. The PostHog browser SDK is not initialized in `apps/web`; the env gate is in place so init can be added without a code change.

Neither var activates anything today — no Sentry or PostHog SDK is wired to receive the data. Only `OTEL_EXPORTER_OTLP_ENDPOINT` produces live telemetry end to end.

## Local development

Both providers stay inactive without configuration. The starter ships no hosted observability service and no free-tier project key.
