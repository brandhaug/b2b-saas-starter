## Public Site (`apps/web`)

- TanStack Start with SSR, served by Vite via the `@cloudflare/vite-plugin` locally and deployed as a Cloudflare Worker
- Public Showcase Site routes (landing, docs, blog, FAQ, pricing, changelog)
- Published Merchant reads and canonical booking ingress through the `BOOKING` service binding
- No authentication routes, session cookies, or platform-administration authority

## Merchant App (`apps/merchant`)

- Merchant-only Better Auth realm and host-only cookie namespace
- Merchant catalog, scheduling, Appointment, integration, and reporting work
- Top-level POST exchange for an approved Operations impersonation handoff

## Operations App (`apps/operations`)

- Separate staff-only origin, Better Auth secret, trusted origins, and host-only Operator Session
- Controlled operator provisioning, enrollment, recovery, role and session management
- Merchant discovery, accountable impersonation, and protected global audit review
- Dedicated rate-limit categories and mandatory production email readiness

Cloudflare Access is deferred. The Operations App's own authentication, current-state authorization, and audit controls are required without it.

## Booking App (`apps/booking`)

- Customer booking session, availability, hold, checkout, and Confirmation flows
- Private production Worker reached only through the Public Site binding

## API Worker (`apps/api`)

- Serves the `StarterApi` HttpApi contract from `packages/api` directly via `HttpRouter.toWebHandler` — routing, schema decoding, OpenAPI, and the Scalar UI all derive from the contract, with no parallel route table (ADR 0039). Hono is intentionally avoided.
- Workspace-scoped API Tokens: `Authorization: Bearer …` parsing, `ApiTokenRegistry.verifyBearerToken(token, requiredScope)`, and `ApiTokenRegistry.create`/`revoke` routes (both requiring `WorkspaceContext`) with `api_token.created`/`.revoked`/`.used` Audit Events
- Per-bucket Cloudflare `RateLimit` bindings (`RATE_LIMITER_REST`, `RATE_LIMITER_REST_WRITE`, `RATE_LIMITER_INVITATIONS`, `RATE_LIMITER_ASSISTANT`, `RATE_LIMITER_MCP`)
- MCP discovery skeleton at `/mcp`; tool dispatch lands on top of the same capabilities
- OpenAPI document at `/openapi.json` and Scalar reference UI at `/reference`

External clients hit the API Worker. Internal UI hits its own server functions. Both paths share `@b2b-saas-starter/capabilities` so business behavior cannot drift.

## Background Worker (`apps/background`)

- Queue and cron recovery for durable booking and Operations notification intents
- Email and signed Webhook delivery with idempotent retry evidence

All six Workers share D1 where necessary, but browser credentials remain scoped to their owning application boundary.
